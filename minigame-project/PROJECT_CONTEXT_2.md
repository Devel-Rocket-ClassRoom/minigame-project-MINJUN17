## 2. 게임 개요

### 2.1 게임플레이 요약
플레이어는 레스토랑 사장. 가구/조리도구 배치, 직원 고용/업그레이드, 메뉴 개발, 마케팅, 매장 확장을 통해 매출과 평판을 올린다.

**장기 목표**: 매년 발표되는 대한민국 맛집 Top 100에서 1등 달성. 1등 이후에도 지속 플레이 가능.

### 2.2 구현 범위 (사용자 원문)
- 가구(의자, 책상) 및 조리도구 직접 배치
- 영업시간이 시작되면 손님 랜덤 입장 (빈도는 가게 평판/점수에 영향받음)
- 손님은 주문(돈 증가) → 식사(만족도 증가) → 퇴장
- 만족도는 손님 대기시간, 주변 인테리어(조경) 등을 반영해 랜덤 증가
- 돈과 만족도로 더 좋은 가구, 직원 업그레이드, 다양한 메뉴 개발 등을 구매해서 매출을 올림
- 한 달(인게임)마다 재료비(원가 × 팔린 개수), 운영비(가게 크기, 직원 수 비례) 차감
- 일 년(인게임, 실시간 약 1시간)마다 대한민국 맛집 Top 100 발표 (매출, 가게 평판 기준)

## 3. 시간 시스템 (확정)

### 3.1 시간 단위
- **인게임 시간 최소 단위 = 한 달**
- **영업 1사이클 (8시 ~ 24시, 16시간) = 한 달 = 실시간 4분**
- 인게임 1년 = 12개월 = 실시간 48분 (약 1시간)
- "인게임 1일" 개념은 없음

### 3.2 영업 사이클
```
[월 시작: 영업 시작 (08:00)]
        ↓
   영업 진행 (8:00 ~ 24:00, 실시간 4분)
        ↓
[월 종료: 영업 종료 (24:00)]
        ↓
   월말 정산 (재료비 차감, 운영비 차감)
        ↓
   12개월마다 → 연말 Top 100 순위 발표
        ↓
   다음 달 시작 → 반복
```

### 3.3 인게임 시간 진행 속도
- 영업 16시간 = 실시간 4분 = **240초**
- 인게임 1시간 = 실시간 15초

## 4. 손님 흐름 (확정)

### 4.1 상태 흐름
```
ENTER              (입구에서 스폰)
WALK_TO_COUNTER    (빈 카운터로 이동)
WAIT_AT_COUNTER    (카운터 점유, 직원이 음식 가져올 때까지 대기)
PAY                (음식 받음, 결제, 카운터 점유 해제)
WALK_TO_SEAT       (자리로 이동)
EAT                (식사, 만족도 증가)
LEAVE              (퇴장)
```

### 4.2 상세 규칙
- **ENTER**: 입구에서 스폰. 평판/점수에 따라 빈도 결정. → `WALK_TO_COUNTER`
- **WALK_TO_COUNTER**: 빈 카운터 탐색 후 이동. 모든 카운터가 점유 중이면 대기 또는 퇴장(TBD). 도착 → `WAIT_AT_COUNTER`
- **WAIT_AT_COUNTER**: 손님이 카운터 점유. 메뉴 주문. 카운터에 배정된 직원이 조리하러 이동. 대기 시간이 길수록 만족도 페널티. 직원이 음식 가져오면 → `PAY`
- **PAY**: 결제 (돈 증가), 카운터 점유 해제. → `WALK_TO_SEAT`
- **WALK_TO_SEAT**: 빈 자리 탐색 후 이동. 자리 없으면 TBD (그 자리에서 식사? 화내고 퇴장?). 도착 → `EAT`
- **EAT**: TBD초 식사. 만족도 증가 (대기시간, 인테리어 등 반영해서 랜덤). → `LEAVE`
- **LEAVE**: 자리 해제. 출구로 이동. 도착 시 파괴. 만족도 → 평판 반영

### 4.3 구현 노트
- 카운터 점유 상태는 카운터가 관리 (`bool isOccupied`)
- 대기시간 측정: `WAIT_AT_COUNTER` 진입 시간 ~ `PAY` 시간 차이
- 만족도 계산식: TBD

## 5. 직원 흐름 (확정)

### 5.1 카운터-직원 배정
- **카운터 1개당 직원 1명 배정**
- **시작 시 카운터 2개 배치** (즉 시작 직원 수도 그에 맞춤, 초기 자금/제공 여부 TBD)
- 카운터에 직원이 배정되어 있어야 그 카운터가 작동

### 5.2 직원 상태 흐름
```
IDLE_AT_COUNTER    (카운터 뒤에서 대기)
TAKING_ORDER       (손님 주문 받는 중)
WALK_TO_TOOL       (필요한 조리도구로 이동)
USING_TOOL         (조리도구 사용, 시간 소요)
[필요한 도구가 여러 개면 WALK_TO_TOOL → USING_TOOL 반복]
WALK_TO_COUNTER    (카운터로 복귀)
DELIVER_TO_CUSTOMER (손님에게 음식 전달)
→ IDLE_AT_COUNTER
```

### 5.3 상세 규칙
- **IDLE_AT_COUNTER**: 카운터 뒤 정해진 위치에 대기. 손님이 카운터 도착하면 → `TAKING_ORDER`
- **TAKING_ORDER**: 손님과 잠시 상호작용 (1~N초). 메뉴 결정. → 첫 번째 필요 조리도구로 `WALK_TO_TOOL`
- **WALK_TO_TOOL**: A* 길찾기로 조리도구 이동. 도착 → `USING_TOOL`
- **USING_TOOL**: 조리도구 앞에서 N초 대기 (조리 시간). 끝나면 다음 도구 또는 카운터 복귀 결정
- **WALK_TO_COUNTER**: 자기 카운터로 복귀. 도착 → `DELIVER_TO_CUSTOMER`
- **DELIVER_TO_CUSTOMER**: 손님에게 음식 전달. 손님 상태 → `PAY`. 자기는 → `IDLE_AT_COUNTER`

### 5.4 직원 업그레이드
- 돈과 만족도로 업그레이드 가능 (구체적 효과 TBD)
- 예: 이동 속도, 조리 속도, 주문 받는 속도 등 (어떤 스탯을 올릴지 TBD)

### 5.5 직원 추가
- 카운터 추가하면 추가 직원 채용해야 그 카운터 작동
- 채용 비용/일당: TBD

### 5.6 메뉴-조리도구 매핑
- 각 메뉴는 하나 이상의 조리도구를 순회해서 만들어짐
- 예시: 햄버거는 그릴(패티) + 작업대(조립) 순회
